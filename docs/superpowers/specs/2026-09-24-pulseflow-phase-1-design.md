# PulseFlow Phase 1 Design Spec

**状态：** 已确认  
**日期：** 2026-09-24

## 1. 目标

PulseFlow 将需求文字转成前端页面草稿，让设计人员在交付前编辑布局和组件，让前端开发者把已发布页面拉入自己的项目。

Phase 1 的目标是在 48 小时演示周期内，面向前端开发者跑通一条可验证的 T2UI 流程：导入需求、生成并确认 UI-DSL、人工调整设计、预览、发布，再通过 CLI 集成到 Vue 项目。演示必须覆盖一份专线业务样例和一份未参与调试的 holdout 需求。

## 2. 用户与成功标准

- **设计人员**：查看 T2UI 生成的页面草稿，增删、排序组件，并编辑白名单内的属性和布局。
- **前端开发者**：确认结构化需求和页面草稿，发布页面，再通过 CLI 将生成文件拉入自己的项目。
- **管理员**：配置模型服务端点。Phase 1 不提供公开的默认模型服务。

演示成功需满足：

1. 专线样例和 holdout 需求都能走完需求导入、草稿确认、预览和发布流程。
2. 设计人员可在画布和 Monaco 代码视图之间修改受支持的页面 AST，两个视图保持同步。
3. 生成结果能通过发布硬门槛，并可被 CLI 拉入一个干净的 Vue 3 项目。
4. CLI 检测到本地生成文件已被修改时会停止，提供差异，并保持目标文件不变。

## 3. Phase 1 范围

### 包含

- 输入粘贴的需求文字或 `.docx` 文件。
- 自动呈现文档标题/章节供用户选择；没有可用标题时允许手动选择或粘贴需求片段。
- T2UI 将需求解释为待确认的实体草稿和 UI-DSL 页面草稿。
- 设计人员通过画布或 Monaco 修改受支持的 UI-DSL 视图 AST。
- 以样例数据和 mock handler 预览页面。
- 发布通过校验的不可变页面版本。
- CLI 使用 `PULSEFLOW_TOKEN` 认证，将最新已发布版本拉入 `src/views/<pageId>`，并打印路由接入片段。
- 单工作区认证；不提供团队角色或 SSO。

### 不包含

- D2C 图像/截图输入。Phase 2 再支持截图或设计输入，并将其转换到同一 UI-DSL。
- 从自然语言推断 API、业务逻辑或实际服务端行为。
- 任意 CSS、任意 JavaScript、任意组件代码编辑。
- CLI `push`、MR 自动化、团队角色、SSO。
- 全离线部署、私有组件适配器，以及本地 AST 三方合并；这些属于后续阶段。

## 4. 用户流程

1. 用户新建页面草稿，粘贴需求文字或上传 `.docx`。
2. PulseFlow 展示章节选择器。若文档没有可识别标题，用户手动选择或粘贴目标需求片段。
3. T2UI 生成实体草稿和页面 UI-DSL。用户确认实体和页面结构；未解决的业务语义必须明确标记，并阻止发布。
4. 设计人员在画布中增删、排序白名单组件，编辑组件属性和布局。也可在 Monaco 中编辑对应的受支持视图 AST。
5. 画布与 Monaco 对支持的 AST 双向同步。代码无法解析时保留最近一次有效预览并显示诊断；遇到不支持的语法时报告诊断，不静默丢弃内容。
6. 预览使用样例数据和 mock handler。生成内容包括类型、视图和事件接口；不生成 API 调用或业务实现。
7. 用户运行校验并发布。发布产物包含确认后的 DSL 和生成代码，并带有不可变版本标识。
8. 前端开发者在目标项目中运行 CLI。CLI 拉取最新已发布版本到约定目录，并打印路由接入片段。

## 5. 设计编辑与 UI-DSL

UI-DSL 是确认后的页面定义的唯一规范状态。T2UI、画布、Monaco、预览和代码生成都围绕同一份 DSL 工作；输入来源不直接决定最终生成代码。

DSL 至少包含稳定节点标识、组件类型、组件属性、布局关系和受支持的插槽内容。Phase 1 的组件白名单为：

- `Card`
- `PageHeader`
- `Form`、`FormItem`
- `Input`、`Select`、`Button`
- `Table`
- `Row`、`Col`
- `Tag`、`Badge`

只支持白名单组件及其定义过的属性。画布允许增删和重排组件、修改属性与布局；不允许写任意 CSS 或任意代码。Phase 1 需支持 `PageHeader.tags` 和 `Table.bodyCell` 插槽，并覆盖专线样例中的状态条件展示。生成模板应提供项目内的 `PageHeader` 包装组件，以稳定承载标题与 `tags` 插槽，不依赖 UI 库是否内置同名组件。

字段校验支持必填、枚举和常用格式预设，包括手机号、统一社会信用代码。无法确定的业务语义阻止发布。未指定的布局和视觉样式使用默认值，不要求模型猜测。页面采用 Vue 3、TypeScript、Vite 和 Ant Design Vue 4；使用确定性的表单/表格布局及 Ant Design Vue 默认 tokens。

## 6. 架构边界

实现按以下职责划分，内部部署形态不在本规格中固定：

- **需求导入与解析**：接收文字或 `.docx`，提取标题/章节并支持手动选区。
- **T2UI 生成**：通过管理员配置的模型端点生成实体草稿和 UI-DSL 草稿；将未解决的业务语义显式返回给用户。
- **DSL 校验**：校验组件白名单、属性、插槽、字段规则和页面结构，并向编辑器、预览和发布返回诊断。
- **设计编辑器**：提供组件画布和 Monaco 视图；两者针对同一受支持视图 AST 同步。
- **预览与生成**：使用隔离的样例数据/mock handler 展示 DSL，并生成 Vue 页面、TypeScript 类型和事件接口。
- **发布与版本存储**：保存用户确认的 DSL 和生成代码；每次发布产生不可变版本。
- **CLI**：通过 PulseFlow 服务认证并下载发布产物，不在 Phase 1 回传本地修改。

Phase 1 允许网络访问并使用演示数据。原始 `.docx` 和解析后的需求文字仅用于处理；处理后删除。确认后的 DSL 和生成代码持久化。全离线部署属于 Phase 2。

## 7. 错误处理与发布门槛

- 文档标题无法提取时提供手动选区/粘贴入口；文件无法解析时给出可操作错误，不生成伪造的空页面。
- 未解决的业务语义、无效 DSL、预览编译失败、类型检查失败或干净模板构建失败，均阻止发布。
- 画布或代码编辑产生无效 AST 时，保留最近一次有效预览，并显示可定位诊断。
- 不支持的代码语法必须报告诊断；不得假装同步成功或静默覆盖用户输入。
- ESLint 在 Phase 1 作为提示项，不阻止发布。
- 发布硬门槛依次覆盖 DSL 校验、预览编译、类型检查和干净模板构建。发布版本只能读取，编辑需创建新草稿并发布新版本。
- CLI 首次拉取到不存在的目标目录时创建文件。若目标目录中存在由 CLI 管理的文件，CLI 应使用上次拉取清单/校验值检查本地改动；检测到改动时输出差异并停止，目标内容保持不变。CLI 不提供 push 或自动合并。

## 8. CLI 使用约定

- 认证令牌通过 `PULSEFLOW_TOKEN` 提供，不写入生成源码或日志。
- CLI 拉取指定页面的最新已发布不可变版本，目标路径为 `src/views/<pageId>`；`pageId` 必须校验为单一路径段，不能包含路径穿越或分隔符。
- CLI 成功时报告页面标识和版本，并打印可复制的路由接入片段。
- 若认证、网络或版本读取失败，CLI 给出失败原因并保留现有文件。
- 若发现本地受管文件被修改，CLI 输出本地内容与目标发布版本的差异后退出，不覆盖文件。

预览和生成器只处理白名单 UI-DSL；不得执行从需求或 Monaco 内容中任意注入的 JavaScript。模型端点调用失败时显示可操作错误，并保留已保存的 DSL 草稿和设计修改。

## 9. 验收场景

1. 使用 `.docx` 导入专线样例，选取章节并生成实体草稿及页面 DSL；无标题文档可通过手动输入继续。
2. 设计人员在画布中调整表单/表格布局、重排组件，并检查 Monaco 视图同步；在 Monaco 中编辑受支持节点后画布也更新。
3. 预览覆盖 `PageHeader.tags` 与 `Table.bodyCell` 的状态展示，交互由 mock handler 响应，不触发真实 API。
4. 对缺少必填信息或存在未解决业务语义的草稿，发布被阻止并显示诊断；补全后可继续。
5. 无效代码输入不会替换最后一次有效预览；不支持的语法会显示诊断。
6. 发布前运行四项硬门槛；任一失败阻止发布，ESLint 问题只显示为提示。
7. CLI 在空目标路径成功拉取已发布页面并打印路由片段；再次拉取时若检测到本地改动，能显示差异且不改变本地文件。
8. 页面发布后，原始 `.docx` 和需求文字已删除，确认后的 DSL 和生成代码仍可读取。
9. 同一流程在一份未参与调试的 holdout 需求上成功运行，以验证其不依赖专线样例的固定内容。

## 10. 后续阶段

Phase 2 增加 D2C 输入（截图或设计稿）并映射到 Phase 1 使用的同一 UI-DSL；再评估离线部署、私有组件适配器、SSO、MR 自动化和基于 AST 的本地三方合并。
