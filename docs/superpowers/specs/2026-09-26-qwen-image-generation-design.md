# 对话式页面生图设计

## 目标

让 PulseFlow 在现有对话式页面生成和编辑流程中识别图片需求，按需调用 `qwen-image-2.0`，并允许设计人员在发布前查看、替换或移除图片。生成的图片可用于页面中的 `<img>` 和首屏/内容区背景，且在 Studio 预览、发布版本和 CLI 导出中保持一致。

图片模型和文本模型使用同一 API Key 及网关基础地址。图片模型单独配置为 `qwen-image-2.0`，图片接口 URL 与协议模式可配置，避免将图片请求错误地发送到 `/chat/completions`。

## 项目现状

- `packages/model-adapter` 当前只实现 OpenAI Chat Completions；配置只包含一个文本模型名，接口固定追加 `/chat/completions`。
- `/api/drafts/refine` 接收完整 UI-DSL 并返回校验后的页面；Studio 通过 revision 检查防止迟到响应覆盖手工编辑。
- UI-DSL 使用 Zod 白名单；页面生成器分别生成 Vue 页面文件和静态预览节点。
- 发布版本以 JSON 保存生成文件；CLI 的文件内容和哈希按 UTF-8 文本处理，路径目前限定在 `src/generated/`。
- Qwen 官方图像接口使用与 Chat Completions 不同的同步多模态接口。TokenRhythm 公开模型目录列出 `qwen-image-2.0` 在线，但公开接入文档没有给出图像调用路径；其模型能力信息也未宣称支持 OpenAI 对话协议。因此接口 URL、请求/响应适配器必须独立配置，不能仅从文本模型地址推断协议兼容。
- 现有设计规范排除了任意远程图片 URL、自定义 CSS 和脚本。本功能会扩展为仅允许服务端登记、校验并随版本交付的项目图片资源。

## 方案

### 对话意图与生图时机

设计对话先由文本模型返回受 schema 校验的结构化结果，包含意图 `page_edit`、`image` 或 `page_edit_and_image`，以及可选的图片说明和放置目标。页面编辑仍返回完整 DSL；图片模型只在用户明确要求生成、添加或替换配图时调用。只提到颜色、风格或“更美观”但没有要求图片时，模型可提出建议，不自动发起可能计费的请求。

对模糊意图，Studio 显示“仅调整页面”或“同时生成配图”的确认操作。明确生图意图使用单张默认输出，避免无意增加张数和费用。组合需求先由文本模型返回页面 DSL、图片描述和放置目标，再请求图像模型；图像生成成功并通过校验后才把资源引用加入 DSL。图像生成失败时仍应用有效的页面调整并报告图片失败，不保存半成品资源。所有结果在应用前检查草稿 revision；如果用户在请求期间继续编辑，迟到的结果不覆盖当前画布，完成的图片保留为未应用资源供用户选择。

### 图片模型适配

新增独立的图像模型配置与 provider 接口：

- 默认模型名为 `qwen-image-2.0`。
- 默认复用现有 `PULSEFLOW_MODEL_BASE_URL` 和 `PULSEFLOW_MODEL_API_KEY`；允许通过图片专用环境变量覆盖完整接口 URL 和 API Key，方便兼容特定网关。
- 图片协议使用明确的配置模式，例如 OpenAI Images 兼容模式或 DashScope 原生模式。不得自动猜测响应格式或回退到另一协议，以免掩盖网关配置错误或发出意料之外的请求。
- 统一 provider 输出为 PNG 字节、媒体类型、宽高及请求追踪信息。支持供应商返回 base64 或临时下载 URL；URL 下载要限制协议、目标地址、跳转、超时、响应大小和图片格式，阻止 SSRF 与资源耗尽。
- 超时、上游 HTTP 错误、响应格式错误和图片校验失败分别映射为可读错误；服务端日志保留脱敏后的状态和追踪 ID，不记录 API Key 或完整图片提示内容。

图片接口字段使用 `PULSEFLOW_IMAGE_MODEL_NAME`、`PULSEFLOW_IMAGE_API_URL` 与 `PULSEFLOW_IMAGE_API_MODE`；模型名默认为 `qwen-image-2.0`，URL 默认为现有模型基础地址加 `/images/generations`，模式默认为 `openai-images`，未设置图片专用 API Key 时继承 `PULSEFLOW_MODEL_API_KEY`。若网关需要专用路径/协议，管理员可配置模式和完整 URL。默认只表示采用常见 OpenAI Images 请求格式，不代表 TokenRhythm 已公开保证兼容。README 说明模型目录有该模型并不等于公开 HTTP 协议已确认；正式连通性验收需在拥有该网关的环境里通过 Studio 显式操作完成。本地开发和自动化校验不调用真实计费接口。

### 图片资源与 DSL

图片生成完成后，服务端将校验通过的 PNG 存入 API 管理的资源目录，并在 SQLite 保存资源 ID、媒体类型、字节数、像素尺寸、SHA-256、创建时间和关联草稿。资源 ID 为安全字符集生成，不采用模型提供的路径或文件名。

DSL 只引用资源 ID，不接受远程 URL 或 data URL：

- 新增 `Image` 组件，包含 `assetId`、`alt`、`fit` 和可选比例。
- `Hero` 与 `ContentSection` 可选 `backgroundAssetId`；背景覆盖方式和遮罩通过预定义选项表达，不接受任意 CSS。
- 新生成的页面和修订后的页面都必须验证资源引用属于该工作区且已登记。
- 设计人员可在图片预览中选择应用、重生成或移除图片；画布属性编辑器可调整替代文本、显示方式及背景呈现选项。

生成图片提示由服务端从用户需求和当前页面语境构造，限制长度并过滤控制字符；页面模型只负责返回图片意图、简短图像说明及合法放置目标，不得生成图片 URL、文件路径或 CSS。

### 预览、发布与 CLI 导出

Studio API 的受保护图片读取接口返回登记资源。Studio 通过带 Bearer 认证的 `fetch` 读取图片并创建可撤销的 Blob URL，供 `<img>` 和 CSS 背景预览使用；认证令牌不放入图片 URL。

发布时，服务端从 DSL 收集实际引用的资源并复制为该发布版本的不可变文件，路径固定在 `src/generated/assets/<assetId>.png`。页面代码使用相对静态资源引用，使 CLI 将页面和图片映射到同一个版本目录后仍能正常加载。未引用图片不进入发布包。

发布文件协议扩展为文本或 base64 编码二进制的判别联合：二进制内容只在 JSON 传输时 base64 编码，服务端存储和 CLI 写入使用原始字节；SHA-256 针对原始字节计算。CLI 校验安全相对路径、编码、PNG 标记和哈希后以字节写入。冲突检测按文件字节计算哈希，二进制冲突不生成乱码文本 diff；原子替换和回滚均按字节处理，现有文本文件行为保持不变。发布 manifest 必须精确列出页面和被引用图片文件。

### 发布门禁与错误处理

发布继续运行 DSL 校验、预览编译和页面构建，不恢复 TypeScript 或 ESLint 发布门禁。资产引用缺失、媒体类型不允许、页面引用未登记资源、发布包缺文件或哈希不匹配都要阻断发布，并返回具体资源 ID/文件路径诊断。图片生成失败时保留用户当前 DSL 和画布，不保存半成品资源，不吞掉上游错误。

### 安全与资源限制

- 图片模型仅由 API 服务端调用；浏览器不接触上游 API Key。
- 对提示词长度、生成并发、返回字节数、像素尺寸、图片张数和下载时限设上限；首版每次对话最多生成一张。
- 只接受验证过的 PNG；限制解码后的像素数，校验文件签名，避免仅依赖上游 MIME 声明。
- 资源读取使用工作区认证和资源 ID，不接受任意文件路径；发布路径由服务端生成并由 CLI 再次校验。
- 图片仅按资源引用进入 Vue 模板；不得通过模型内容插入 HTML、脚本、CSS 或远程 URL。
- 不在 CI 或普通单元/集成测试中调用计费的真实生图 API。真实网关验收由用户在 Studio 触发并可观察费用与结果。

## 组件边界

1. **图像模型适配器**：把配置、上游请求和供应商响应统一成校验过的 PNG 字节。
2. **图片资源仓库**：写入/读取二进制资源及元数据，提供安全 ID 和哈希。
3. **对话编排服务**：解析意图，先获取 DSL 修改与图片计划，再按计划调用生图并应用 revision 保护。
4. **DSL/页面生成**：表达 `<img>` 与预定义背景，并生成 Studio renderer 和 D2C Vue 输出。
5. **发布与 CLI 文件传输**：封装只被页面引用的二进制文件，校验 hash 并安全写入本地。
6. **Studio 图片交互**：展示生成状态和费用提示，支持预览、应用、重生成、移除及属性调整。

## 验收标准

1. 普通布局或文案调整不调用图片模型；清晰的生图请求会使用 `qwen-image-2.0`；组合请求能同时得到页面修改和图片资源。
2. 不清楚是否要生图时，Studio 先询问，不产生上游图片调用。
3. 生成资源可放入 `<img>` 或 Hero/内容区背景；设计人员可更换或移除，预览实时一致。
4. DSL 拒绝任意 URL、路径、data URL、未知资源 ID 和任意 CSS。
5. 预览使用受保护资源获取，无密钥出现在浏览器请求或页面产物中。
6. 发布只打包被引用图片；CLI 导出的页面在目标项目中能加载本地 PNG，manifest、哈希、冲突判断和回滚覆盖二进制文件。
7. 上游错误、超时、超限、无效响应和过期草稿均给出可理解反馈且不破坏当前设计。
8. 兼容标准图片接口、协议配置缺失、无效 PNG、资源越权、二进制校验和发布/CLI 往返均有 mock 覆盖；不发起真实计费请求。

## 非目标

- 图片模型直接生成页面代码、任意 HTML、CSS 或脚本。
- 从任意公网 URL 导入图片或允许模型提供远程图片链接。
- 在服务端托管发布后的站点或引入新的图片 CDN。
- 在自动化测试里真实扣费验证上游图像模型。
- 自动批量生成多张备选图。首版默认每个明确意图生成一张，设计人员可发起重生成。

## 接口文档依据与待确认事项

- Qwen 官方图像生成文档：<https://help.aliyun.com/zh/model-studio/qwen-image-api>。`qwen-image-2.0` 支持同步图像生成，接口形状与文本 Chat Completions 不同。
- TokenRhythm 公开模型目录：<https://tokenrhythm.studio/models>。目录列出 `qwen-image-2.0` 在线并标注按张计费。
- TokenRhythm 公共 API 文档：<https://tokenrhythm.studio/docs/api-integration>。公开说明覆盖 OpenAI/Anthropic 对话和 embeddings；当前未找到该图像模型的 HTTP 调用路径/响应 schema。

因此实现必须将图片接口路径和协议适配独立于文本适配器，并在用户提供具体图像 API 格式或通过网关控制台验证后，才能宣称当前网关端到端已连通。开发验收只 mock 上游，不消耗用户额度。
