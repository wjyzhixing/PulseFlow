# 企业页面生成与对话迭代设计

## 目标

PulseFlow 生成的页面要具备企业官网或管理平台的清晰层级、完整布局和一致视觉；用户进入设计画布后，可以继续用自然语言修改当前页面，预览、节点编辑和导出结果保持一致。

## 现状与问题

- 模型提示词把输出限制在 12 种基础组件，适合表单与表格，缺少官网首屏、功能区块、指标摘要等表达能力。
- 预览与导出的页面外壳使用不同的样式，导出模板仍有非企业后台风格的浅绿底色和硬阴影。
- 模型只支持一次性从需求章节生成，`/api/drafts` 没有基于当前 DSL 继续生成的接口，设计页也没有对话入口。
- 页面 DSL 有统一校验器、预览 renderer 和发布构建 gate。新生成和迭代结果都必须经过同一校验链。

## 设计

### 页面类型与视觉结构

需求生成增加页面类型：自动识别、企业官网、管理平台。模型根据选择的类型和需求内容构造页面；自动识别作为默认值，避免破坏现有输入流程。

扩展 UI-DSL 的语义组件，至少覆盖官网的导航/首屏/内容区块/功能卡片/锚点式转化行动区块，以及管理平台的指标摘要；保留已有表单、表格、标签和栅格组件。官网行动区块必须链接到同页已有内容区块，作为页面末尾的明确咨询或转化入口。每个组件的 props、子节点和数据引用都由 Zod schema 白名单约束。模型收到对应页面类型的结构规则和精简示例，不生成任意 HTML、CSS、脚本或 API 调用。

生成页、Studio 预览和 CLI 导出使用一致的 Ant Design 风格主题：白色内容面、浅灰布局背景、蓝色主操作、明确标题层级、统一留白与响应式栅格。发布 gate 继续编译并构建实际导出模板。

### 对话式修改

新增 `POST /api/drafts/refine`。请求包含当前实体字段、完整页面 DSL、未解决问题和一条用户修改指令；服务端验证输入后调用模型。模型返回完整的新草稿，而非可执行代码或任意 patch。服务端用与初次生成相同的 Zod 和 DSL 校验器验证返回值，并要求 pageId 保持稳定。

设计画布提供对话面板，展示用户指令、模型变更摘要和错误状态。只有响应通过校验且本地草稿 revision 未变化时，才应用新的实体字段和页面 DSL；如果请求期间用户手动编辑过，则丢弃过期响应并提示重新提交。成功应用后仍可撤销/继续通过现有节点编辑器调整，保存和发布流程维持原有 gate。

### 错误处理与安全

- 对空指令、过长指令、畸形实体字段/DSL 和模型无效输出返回可读错误。
- 所有需求文本和对话指令仅作为用户数据传入，系统提示词限定模型只返回目标 JSON。
- 返回 JSON 通过严格结构 schema、字段引用检查和 DSL 校验后才可进入 Studio。
- 网络失败、超时、模型结构错误与 DSL 校验失败分别映射为可理解反馈。
- 不把生成文本作为 HTML 执行，不允许 DSL 引入自定义脚本、样式或外部 API。

## 验收标准

1. 页面类型选择能影响模型输出结构；自动识别仍可用于旧的生成流程。
2. 官网和管理平台输出使用语义组件构成不同的信息层次；官网具有首屏行动入口和页面末尾的高对比转化区块，不再只有无样式的卡片/表单/表格堆叠。
3. Studio 预览与导出的 Vue 模板有一致的主题结构，窄屏布局可用。
4. 用户可在设计页提交自然语言修改；有效响应应用到当前页面，结构无效或过期响应不会覆盖画布。
5. 新增 DSL 节点能通过预览 renderer 与现有发布构建 gate；转化行动区块链接只允许引用已存在的内容区块；编辑和发布的既有行为保留。
6. README 的中文使用指南说明页面类型选择、对话修改和错误恢复方式。

## 不在本次范围

- 自动接入真实后端 API、数据库或业务权限。
- 用模型生成并执行任意脚本、CSS、远程图片或第三方 URL。
- 改变当前发布的不可变版本语义。
