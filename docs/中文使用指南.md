# PulseFlow 中文使用指南

## PulseFlow 是什么

PulseFlow 是一个把业务需求整理成 Vue 3 页面草稿的工作台。它适合前端开发者和设计人员一起确认页面结构：先导入需求，再生成并编辑页面，检查预览和发布条件，最后把发布版本拉进实际 Vue 项目。

整个流程分两部分：

1. **Studio 工作台**：在浏览器中导入需求、确认字段和页面结构、编辑组件、预览并发布。
2. **PulseFlow CLI**：在你的 Vue 项目中下载已发布页面，生成页面文件和路由接入提示。

PulseFlow 生成的是受支持组件组成的页面骨架。预览使用样例数据和模拟交互；实际业务 API、数据读写和应用路由仍需在你的项目中接好。

## 开始前准备

- Node.js 22 或更新版本
- pnpm 10.33.0
- 一个兼容 OpenAI Chat Completions 接口的模型服务，以及对应的模型名和 API Key

先在项目根目录安装依赖并准备环境配置：

```sh
corepack enable
corepack prepare pnpm@10.33.0 --activate
pnpm install
cp .env.example .env
```

打开 `.env`，至少设置以下内容：

```dotenv
PULSEFLOW_WORKSPACE_TOKEN=换成一段足够长的随机令牌
PULSEFLOW_DB_PATH=./data/pulseflow.sqlite
PULSEFLOW_MODEL_BASE_URL=https://你的模型服务地址/v1
PULSEFLOW_MODEL_NAME=你的模型名称
PULSEFLOW_MODEL_API_KEY=你的模型服务密钥
```

模型服务地址填写基础地址即可，PulseFlow 会在后面拼接 `/chat/completions`。模型服务需要支持 JSON Object 格式的响应。请勿把真实令牌或模型密钥提交到 Git。

PulseFlow 不会自动读取 `.env`。每次启动前，在终端执行以下命令，将配置加载到当前终端：

```sh
set -a
source .env
set +a
```

## 启动工作台

保持上一步的终端打开，在项目根目录启动 API：

```sh
pnpm --filter @pulseflow/api dev
```

再打开一个终端，进入同一项目目录，加载同一份 `.env` 并启动 Studio：

```sh
set -a
source .env
set +a
pnpm --filter @pulseflow/studio dev
```

在浏览器打开终端显示的地址，通常是 <http://localhost:5173>。输入 `.env` 中 `PULSEFLOW_WORKSPACE_TOKEN` 的值登录。Studio 默认通过 API 服务的 3000 端口访问后端；若 API 使用其他地址，可在启动 Studio 前设置 `PULSEFLOW_API_URL`。

## 在 Studio 中生成并发布页面

1. **导入需求**：粘贴需求文字，或上传不超过 10 MB 的 `.docx` 文件，然后解析内容。
2. **选择页面类型和章节**：可选自动识别、企业官网或管理平台，再勾选要用于生成页面的章节。企业官网会优先组织导航、首屏、不同目的的内容区块，并在页面末尾加入可定位到联系区块的行动入口；管理平台会优先组织指标、筛选表单和数据表。若原文没有可识别章节，可以手动添加需求片段。
3. **生成并确认草稿**：PulseFlow 调用已配置的模型生成实体字段和页面 UI-DSL。检查字段、页面结构及需要补充回答的问题，修正后确认保存。
4. **编辑画布和对话调整**：在画布中选择节点、添加或调整受支持的组件，在属性面板修改内容和字段绑定；也可以编辑 JSON。中间画布列内的“对话调整页面”可以根据当前画布继续修改，例如调整首屏重点、重排指标和表格、精简页面文案。对话会保留当前页面类型；要在企业官网和管理平台之间切换，请回到需求生成页选择类型并生成新草稿。只有通过 UI-DSL 校验的结果会应用；如果你在模型处理期间手动编辑过页面，旧结果会被丢弃，按提示基于最新页面重新提交即可。
5. **检查预览**：预览用模拟数据展示页面，并与导出的页面共用主题样式。此时不会连接你真实项目中的业务 API。
6. **发布**：点击“运行检查并发布”。DSL 校验、预览编译、干净模板构建是发布门槛；任何一项失败都需要先处理诊断。

也可以点击“从空白画布开始”手工创建页面，不经过需求解析和模型生成。

发布版本是只读的。发布后继续编辑会形成新草稿，需要再次通过检查并发布，才会产生新版本。

## 把发布页面拉进 Vue 项目

在 PulseFlow 项目根目录构建 CLI：

```sh
pnpm --filter @pulseflow/cli build
```

然后在**你的 Vue 项目根目录**运行以下命令。将 `你的页面ID` 替换成 Studio 页面显示的 PAGE ID；令牌使用 PulseFlow 工作区令牌：

```sh
PULSEFLOW_TOKEN="你的工作区令牌" node /PulseFlow项目的实际路径/packages/cli/dist/main.js pull 你的页面ID --base-url http://localhost:3000
```

例如，若 PulseFlow 仓库位于 `/Users/me/PulseFlow`，页面 ID 是 `dedicated-line_1`：

```sh
PULSEFLOW_TOKEN="你的工作区令牌" node /Users/me/PulseFlow/packages/cli/dist/main.js pull dedicated-line_1 --base-url http://localhost:3000
```

CLI 会将页面文件写入当前 Vue 项目的 `src/views/<页面ID>/`，同时更新 `.pulseflow/manifest.json`，并在终端打印路由配置片段。请按提示把路由片段接入项目的 Vue Router；CLI 不会自动改你的路由，也不会替你安装依赖。

如果已经通过 `source .env` 加载过配置，`.env` 里的 `PULSEFLOW_WORKSPACE_TOKEN` 不会自动作为 CLI 令牌。运行 CLI 前请设置 `PULSEFLOW_TOKEN`，例如：

```sh
export PULSEFLOW_TOKEN="$PULSEFLOW_WORKSPACE_TOKEN"
```

下次拉取时，如果 CLI 发现之前生成的文件已被本地修改，它会显示差异并停止，不会覆盖这些本地修改。请先自行保存或处理修改，再决定如何继续。

## 常见问题

### 打开 Studio 后要求登录，或者令牌无效

确认输入的是 API 使用的 `PULSEFLOW_WORKSPACE_TOKEN`，并确保 API 进程启动时已加载同一个 `.env`。如果修改了配置，重启 API 和 Studio。

### Studio 显示模型连接、生成或页面调整失败

检查 `PULSEFLOW_MODEL_BASE_URL`、`PULSEFLOW_MODEL_NAME` 和 `PULSEFLOW_MODEL_API_KEY` 是否正确，确认当前运行 API 的终端已加载环境变量，并确认模型服务接受 Chat Completions JSON Object 请求。

### DOCX 没有解析出可选章节

确认文件是 `.docx` 且小于 10 MB。也可以直接粘贴需求文字，或在章节选择区域手动添加需求片段。

### CLI 无法下载页面

确认页面已经发布、页面 ID 填写正确、`PULSEFLOW_TOKEN` 已设置，并且 `--base-url` 指向正在运行的 PulseFlow API。

### 发布被阻止

查看发布面板中的诊断，修复 DSL、预览编译或模板构建失败的问题后重试。未回答的业务语义问题也可能需要先补充。

## 当前版本的范围

- 支持粘贴需求文字和导入 `.docx`；需求原文仅用于处理，不保存在草稿或发布记录中。
- 页面由受支持的组件和属性组成，支持企业官网的首屏、内容区块与转化行动入口，以及管理平台常用页面结构；不支持任意 CSS、JavaScript 或通用代码生成。
- 页面生成后可在设计画布中继续通过对话调整；每次修改仍须通过 UI-DSL 校验。
- 预览数据和交互为模拟内容，不会实现实际业务服务。
- CLI 只拉取已发布页面，不会自动修改应用路由，也不会把本地改动推回 PulseFlow。
- 本地确定性演示可运行 `pnpm e2e`，但它使用合成需求和假模型，不代表外部模型或真实业务需求已通过验收。
